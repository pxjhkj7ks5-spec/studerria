# Цивільні оголошення Telegram

Джерела: публічні вебсторінки `AerisRimor`, `kyiv_airdef`, `kievinform_ua1`. Координати точок користувача не надсилаються каналам, геокодерам чи картографічним провайдерам. Модуль зіставляє явно названі населені пункти; не визначає координати, напрямок чи рух загроз.

## Радіус та мапа

Для наявних і нових зон `bulletinRadius !== false` автоматично включає поселення, довідниковий центр яких перебуває на відстані до `radiusKm` включно (haversine, 1–100 км). `data/settlements.json` містить 32 483 записи GeoNames України; джерело, ліцензія й контрольна сума наведені в `data/README.md`. Центр поселення не є його територіальною межею; повнота, назви та координати можуть мати похибки. Додаткові `bulletinAreas` збережено, як і успадкування їхніх районів/області.

У редакторі зони показується локальна SVG-мапа центрів поселень з колом, позначкою півночі та повним списком знайдених місць. Масштаб змінюється разом із радіусом. Зовнішні тайли не завантажуються. Авторизований `POST /api/v1/zones/preview` перевіряє координати й радіус, не зберігає точку та повертає лише довідникові поселення.

Згадка назви з радіуса достатня для цивільного сповіщення після відсівання історичних, навчальних, рекламних і заперечених фраз. У старих адміністративних підписках потрібна попереджувальна фраза. Кириличні альтернативні назви та обмежені відмінки беруться з довідника; для відомих міст збережено ручні відмінки. Нечітке зіставлення застосовується лише до старого невеликого словника. Однойменні поселення залишаються неоднозначними: повідомлення означає збіг назви, а не підтвердження загрози саме біля точки.

## Балістика та повтори

Слова `балістика`, `балістичний`, `баллистика`, `ОТРК` у поточному незапереченому повідомленні створюють HIGH. Якщо місце не назване або не розпізнане, це **загальне** попередження без прив'язки до точки; його можна вимкнути через `ballisticWarnings=false`. Явний відбій/спростування не є новим попередженням. Розбір евристичний і може помилятися.

Перша придатна згадка одразу ставиться у звичайний зашифрований outbox, без очікування другого джерела. Повтор для того самого користувача приглушується, якщо всі відповідні місця вже охоплені попереднім повідомленням того самого рівня терміновості та час публікації відрізняється не більш ніж на `OBRIY_BULLETIN_COOLDOWN_MS=15000`. Невизначеність формулювання не створює дубль. Нове місце чи посилення до HIGH не приглушуються. Це групування сповіщень, не ототожнення об'єктів.

«Одразу» означає після отримання й обробки: вебсторінки опитуються раз на 15 секунд, timeout 10 секунд; затримки Telegram, rate limits і повторні спроби можуть збільшити час. Вебперегляд не є гарантованим потоковим API (https://core.telegram.org/widgets/post). Гарантії доставки за 15 секунд немає.

## Доставка і відновлення

`shadow` збирає дані без доставки; `live` разом з `OBRIY_BULLETIN_APPROVED=true` дозволяє відправлення. Достатньо одного ініціалізованого доступного джерела. Колишній 24-годинний бар'єр для всіх трьох каналів прибрано; початковий знімок і дописи з незавершеної прогалини, як раніше, не розсилаються. Курсори, backfill, ревізії та черга зберігаються в PostgreSQL; джерела й обробник мають окремий стан здоров'я.

Перед відправленням перевіряються пауза, прив'язка Telegram, зона та її ревізія, ревізія повідомлення, свіжість конкретного каналу (90 секунд), вік допису (180 секунд) і режим. Недоступність іншого каналу чи NEPTUN не блокує придатне цивільне повідомлення. Правка скасовує застарілу чергу, а спростування вже доставленого попередження створює уточнення, не офіційний відбій. Bot API не має idempotency key: після втрати відповіді можлива невизначеність доставки.

## Серверне ввімкнення

Після отримання нової версії, з кореня KMA:

```bash
git pull --rebase
bash scripts/server-update-obriy.sh --live
```

Параметр `--live` зберігає лише три параметри цивільних оголошень у `docker/local/.env` (`live`, `true`, `15000`), зберігає інші значення та запускає стандартне оновлення **тільки obriy**. Без `--live` wrapper не змінює режим. Для вимкнення розсилки оператор повертає `OBRIY_BULLETIN_MODE=shadow` та запускає `bash scripts/server-update.sh obriy --no-build`.

Перевірки: `npm run check:bulletins` (жива доступність без виводу дописів), `npm run typecheck`, `OBRIY_TEST_DATABASE_URL=... npm test` (окремі тимчасові БД), `npm run build`. Тести не є підтвердженням фактичного отримання повідомлень у Telegram. Точні причини пропусків на сервері потребують його діагностики; локальний код не доводить поточний стан production.
