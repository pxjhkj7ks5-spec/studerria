# Приватність

Обрій обробляє точні зони на вашому VPS. Це server-first модель: власник VPS і процес застосунку технічно мають доступ до розшифрованих координат. AES-256-GCM захищає поля в базі, але не скомпрометований сервер.

Браузер звертається лише до власного сервісу. Немає сторонніх карт, геокодера, шрифтів, аналітики, iframe NEPTUN або service worker, який кешує персональні дані. Одноразове визначення поточної позиції запускається лише кнопкою користувача; координати передаються нашому серверу після збереження зони. Визначення місцеположення самим браузером залежить від платформи та її дозволів.

NEPTUN бачить IP сервера та час з'єднання; alerts.in.ua також бачить власний API-токен. Їм не передаються координати зон, назви зон, радіуси, chat ID чи IP клієнта. Вихідні URL незмінні; жодних користувацьких query-параметрів. Telegram бачить зв'язок із ботом і надіслані тексти. Чат із ботом не є Secret Chat. Повідомлення містять лише тип загрози, грубий діапазон відстані та загальне пояснення; без точної адреси, координат або назви зони. Чутливі повідомлення не логуються.

Координати/назви/регіон зони, оцінки ризику, chat ID та outbox payload шифруються з прив'язкою до поля й власника. Індекс chat ID — HMAC. Ключ шифрування знаходиться лише у runtime env поза PostgreSQL. Спільний ключ відкриває лише реєстрацію та вхід. Особистий доступ — логін і пароль зі стійким salted scrypt-хешем; сесія непрозора, HttpOnly, SameSite=Strict, у production Secure. `.env` має права 600. Rate limits обмежують вхід і команди; HTTP request logging вимкнено.

До входу сервер віддає лише окрему сторінку для ключа доступу, без HTML кабінету. Прямий шлях `index.html` теж перевіряє сесію, а статична роздача HTML вимкнена. Ключ не записується в localStorage/sessionStorage. Публічний endpoint стану джерел залишається доступним для моніторингу без зон і персональних даних.

## Видалення та строки

Кнопка «Видалити мої дані» або `/delete_me` видаляє користувача, акаунт із хешем пароля, зони, сесії, pairing codes, оцінки, чергу, підписки та пов'язані журнали доставок через FK cascade. Неідентифікуючі номери оброблених Telegram updates зберігаються до 7 днів для дедуплікації; зв'язку з користувачем там немає. Команда `/delete_me` може не отримати підтвердження в Telegram при мережевій помилці, хоча дані вже видалені. Після видалення акаунту нова реєстрація створює порожній профіль; чужі акаунти не змінюються.

Видалення з робочої бази не відкликає вже надіслані Telegram-повідомлення й не стирає раніше зроблені резервні копії. Власник має застосувати кінцевий строк резервних копій (рекомендовано 7 днів) та після відновлення повторити запити на видалення до увімкнення доставки. Зашифрований off-site backup конфігурується оператором; він не підключений автоматично до невідомого сховища.

Raw upstream events: 24 години за замовчуванням, максимум 72. Поточні/застарілі треки й точки: 7 днів. Оцінки, доставки та службові події: 30 днів, конфігурується 1–90. Очищення на старті та щогодини. Дані зон — до видалення користувачем. Параметри в `.env.example`.

Інфраструктурні журнали існуючого reverse proxy можуть містити IP та URL клієнта. Координат і ключів у URL немає. Оператор має окремо налаштувати обмеження доступу/retention цих журналів; Обрій не переписує чужі серверні конфігурації.
